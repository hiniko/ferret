# Vector search & embeddings

pgvector approximate-nearest-neighbour over HNSW (cosine). Embeddings come from a pluggable
`IEmbeddingProvider`; model and dimensions are always configurable (never hardcoded) and the
dimensions drive the physical `vector(N)` sidecar column. Schema (column + HNSW index +
`ferret_vector_versions` registry) is generated by `Ferret.Migrations`
([migrations.md](migrations.md)).

## Annotate

`[Searchable(Backend = SearchBackend.Vector, ...)]` goes on the **string** property holding the
source text to embed — not on a `float[]`/`Vector` column. Ferret generates the physical
`vector(N)` sidecar column and embeds on write; you never store or read the vector yourself.

```csharp
[SearchableEntity]
public sealed class Doc : ISearchableEntity<Guid>
{
    public Guid Id { get; init; }

    [Searchable(Backend = SearchBackend.Vector, Group = "content", EmbeddingDimensions = 768)]
    public string Body { get; init; } = "";
}
```

`EmbeddingDimensions` must match the connector's output dimensionality (768 for
`nomic-embed-text` above) and is required — the group build fails if it's unset. `Group`
behaves as in full-text: properties sharing a group share one embedding column, and the group
name is what you pass to `ReindexAsync<T>(session, "<group>")` below. A property can also carry
a second `[Searchable(Backend = SearchBackend.FullText, ...)]` attribute to opt the same entity
into hybrid search — see the worked example in
[full-text-search.md#hybrid](full-text-search.md#hybrid).

## Connectors

Pick one when enabling vector search:

```csharp
// OpenAI (or any OpenAI-compatible /v1/embeddings endpoint)
.UseVectorSearch(v => v.UseOpenAiEmbeddings(apiKey, "text-embedding-3-small", 1536))

// Ollama — local, OpenAI-compatible /v1 (great for dev/CI; nomic-embed-text is 768d)
.UseVectorSearch(v => v.UseOllamaEmbeddings("http://localhost:11434"))

// Any Microsoft.Extensions.AI generator (native OllamaSharp, Azure, etc.)
.UseVectorSearch(v => v.UseEmbeddingGenerator(sp => myGenerator, "model-id", 768))

// Fully custom
.UseVectorSearch(v => v.UseEmbeddingProvider(sp => new MyProvider()))
```

`UseOpenAiEmbeddings` takes an optional `endpoint` (default `https://api.openai.com`) and
`sendDimensionsParam` (default `true`; set `false` for fixed-dimension models like
`nomic-embed-text` that don't accept the `dimensions` request field).

## Reindex

Vector backfill is explicit — the migration creates the schema, then you embed + populate:

```csharp
await engine.ReindexAsync<Doc>(session, "content");
```

## Version transitions

Stored vectors are tracked in a `ferret_vector_versions` registry and live in version-stamped
columns (`<group>_embedding_v1`). Changing the model or dimensions requires re-running
`engine.ReindexAsync<T>(session, "<group>")`. Until you do, vector search **fails loud**
("embedding model/dimensions changed; reindex required") rather than silently searching
incompatible vectors.

v1 keeps a single active version per group. Zero-downtime backfill between versions (serve v1
while building v2) is a planned addition — the registry + version-stamped columns are the
foundation for it.

## Filtering and vector search

Combining a filter with vector search has a caveat that does not apply to trigram or full-text:
a selective filter can return a short page, because the HNSW index is approximate and cannot see
the filter. See [vector-filtering.md](vector-filtering.md) for why, what the wider ecosystem
does, and what to do about it today.
